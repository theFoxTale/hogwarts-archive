# Class Components App

## Технологический стек

- **React** (классовые компоненты, без хуков)
- **TypeScript**
- **Vite** – сборка и разработка
- **ESLint** – статический анализ кода
- **Prettier** – автоматическое форматирование
- **Husky** – pre-commit хуки (запуск `lint` перед коммитом)

## Команды

| Команда           | Описание                                                |
| ----------------- | ------------------------------------------------------- |
| `npm run dev`     | Запуск дев-сервера Vite                                 |
| `npm run build`   | Компиляция TypeScript и сборка проекта через Vite       |
| `npm run preview` | Локальный предпросмотр собранного приложения            |
| `npm run lint`    | Запуск ESLint для всех `.ts` / `.tsx` файлов            |
| `npm run format`  | Автоматическое форматирование всего кода через Prettier |

# Функциональные требования (+100)

### 1. Структура макета приложения (+5)

- [ ] <b>(+5)</b> Страница содержит ровно две основные области: область поиска (вверху) и область результатов (внизу). Обе области визуально различимы и четко разделены.

### 2. Поиск с локальным хранилищем (+15)

- [ ] <b>(+5)</b> При загрузке приложения компонент поиска проверяет `localStorage` на наличие сохранённого поискового запроса.
- [ ] <b>(+5)</b> Если сохранённый запрос существует, он автоматически отображается в поле ввода.
- [ ] <b>(+5)</b> Если сохранённого запроса нет, поле ввода остаётся пустым.

### 3. Отображение результатов поиска (+10)

- [ ] <b>(+5)</b> Каждый результат содержит название элемента (имя персонажа).
- [ ] <b>(+5)</b> Каждый результат содержит описание элемента (дом, вид, пол или другой набор характеристик).

### 4. Начальная загрузка данных (+10)

- [ ] <b>(+5)</b> При начальной загрузке приложение отправляет запрос к API: если в поле поиска есть текст – используется он, иначе запрос возвращает все доступные элементы (первая страница).
- [ ] <b>(+5)</b> Полученные данные корректно отображаются в области результатов.

### 5. Выполнение поиска (+20)

- [ ] <b>(+5)</b> При нажатии кнопки «Search» лишние пробелы в начале и конце удаляются.
- [ ] <b>(+5)</b> Если введённый текст не изменился по сравнению с предыдущим поиском, новый запрос не выполняется.
- [ ] <b>(+5)</b> Запрос отправляется на первую страницу результатов.
- [ ] <b>(+5)</b> Область результатов обновляется новыми данными.

### 6. Сохранение поискового запроса (+5)

- [ ] <b>(+5)</b> При успешном поиске очищенный (trim) поисковый запрос сохраняется в `localStorage`, перезаписывая предыдущее значение.

### 7. Индикация состояния загрузки (+10)

- [ ] <b>(+5)</b> Во время выполнения API-запроса отображается индикатор загрузки (спиннер, скелет, текст «Loading…» и т.п.).
- [ ] <b>(+5)</b> Индикатор скрывается после получения ответа (или ошибки).

### 8. Обработка ошибок (+10)

- [ ] <b>(+5)</b> При ошибке сервера (4xx, 5xx) пользователю показывается понятное сообщение об ошибке.
- [ ] <b>(+5)</b> Консоль браузера остаётся чистой (нет неперехваченных ошибок).

### 9. Граница ошибки (Error Boundary) (+15)

- [ ] <b>(+5)</b> Присутствует тестовая кнопка, при клике на которую в приложении генерируется ошибка.
- [ ] <b>(+5)</b> Ошибка логируется в консоль.
- [ ] <b>(+5)</b> Вместо «сломанного» UI отображается запасной интерфейс (fallback UI).

# Технические требования (штрафы)

- [ ] <b>(-95)</b> Проект **не** инициализирован с помощью [Vite](https://vitejs.dev/) и шаблона `react-ts`.
- [ ] <b>(-95)</b> **TypeScript** не используется.
- [ ] <b>(-20 за каждое)</b> Использование типа `any` (каждое вхождение).
- [ ] <b>(-20 за каждое)</b> Использование `ts-ignore`.
- [ ] <b>(-10 за каждое)</b> Наличие _code-smells_ (божественный объект, дублирование кода, закомментированные участки).
- [ ] <b>(-50 за каждое)</b> Прямые манипуляции с DOM внутри React-компонентов.
- [ ] <b>(-70)</b> Использование React-хуков для доступа к состоянию или жизненному циклу (вместо классовых компонентов).
- [ ] <b>(-100)</b> Использование Redux или других библиотек управления состоянием.
- [ ] <b>(-100)</b> Использование сторонних библиотек компонентов (Material UI, Ant Design и т.п.).
- [ ] <b>(-10)</b> Pull Request не соответствует гайдлайну (включая чекбоксы в Score).
- [ ] <b>(-100)</b> Файлы настройки React находятся в ветке `main` (а не в отдельной `class-components`).
- [ ] <b>(-100)</b> Отсутствует выделенная ветка с именем `class-components`.
- [ ] <b>(-100)</b> Использование React-хуков (повторное правило – штраф дублируется).
- [ ] <b>(-50)</b> Отсутствие декомпозиции компонентов (всё в одном файле или плохая структура).
