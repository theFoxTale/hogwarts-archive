# React: Маршрутизация и хуки

## 🧠 Описание задачи

В этой задаче вы выполните рефакторинг ваших компонентов-классов в функциональные компоненты с хуками и реализуете функциональность маршрутизации. Вы добавите пагинацию, страницы с детальным просмотром и навигацию на основе URL.

## ⚠️ ВАЖНОЕ УВЕДОМЛЕНИЕ

Сосредоточьтесь на маршрутизации и функциональных компонентах.

## 🎯 Цели задачи

- Преобразовать компоненты-классы в функциональные компоненты с использованием хуков React
- Внедрить React Router для навигации и управления URL
- Создать пользовательские хуки для общей логики
- Добавить пагинацию с синхронизацией с URL

## Функциональные требования (максимум **100 баллов**)

### Функция 1: Пагинация (**30 баллов**)

**Как** пользователь
**Я хочу** перемещаться по страницам результатов поиска
**Чтобы** просматривать больше элементов и отслеживать просмотренные элементы

**Сценарий:** Пагинированные результаты с синхронизацией URL

- **При условии**, что я просматриваю список элементов
- **Когда** я перехожу на другую страницу с помощью элементов управления пагинацией
- **Тогда** текущая страница отображается в URL в качестве параметра запроса (например, `?page=2` или `/:page`)
- **И** элементы управления пагинацией отображают текущую страницу
- **И** пагинация появляется только после загрузки списка элементов
- **И** при изменении ввода в строке поиска страница должна сбрасываться на 1, а URL должен обновляться соответствующим образом

**Критерии приемки:**

- Элементы управления пагинацией видны после загрузки элементов. [10 баллов]
- Изменение страницы обновляет URL с правильным параметром `page`. [10 баллов]
- Видимая страница всегда соответствует странице в URL. [10 баллов]

### Функция 2: Режим «Мастер-детали» (**45 баллов**)

**Как** пользователь
**Я хочу** просматривать детали элемента рядом с результатами поиска
**Чтобы** видеть больше информации, не теряя текущую позицию

**Сценарий:** Разделенный вид с панелью деталей

- **При условии**, что я нахожусь на главной странице с результатами поиска
- **Когда** я нажимаю на элемент
- **Тогда** страница разделяется на две секции:
  - Левая секция продолжает показывать результаты поиска
  - Правая секция отображает детали элемента с помощью `<Outlet>` из React Router
- **И** отображается индикатор загрузки, пока детали загружаются
- **И** есть элемент управления «Закрыть», чтобы скрыть секцию с деталями
- **И** по умолчанию, при первой загрузке страницы никакой элемент не выбран
- **И** URL отражает как текущую страницу, так и выбранный элемент (например, `/?page=2&details=1` или `/:page/:detailsId?`)

**Критерии приемки:**

- Нажатие на элемент открывает панель с деталями справа, используя `<Outlet>`. [20 баллов]
- Левая сторона всегда показывает список результатов. [5 баллов]
- Индикатор загрузки виден, пока загружаются детали. [5 баллов]
- Панель деталей может быть закрыта через кнопку закрытия или кликом по основной панели. [5 баллов]
- URL всегда отражает текущую страницу и выбранный элемент. [5 баллов]
- При начальной загрузке никакой элемент не выбран, и панель деталей закрыта. [5 баллов]

### Функция 3: Страница «О приложении» (**15 баллов**)

**Как** пользователь
**Я хочу** просматривать информацию о приложении и его авторе
**Чтобы** узнать больше о приложении и его создателях

**Сценарий:** Навигация на страницу «О приложении»

- **При условии**, что я использую приложение
- **Когда** я перехожу на страницу «О приложении»
- **Тогда** я вижу информацию об авторе и ссылку на курс RS School React
- **И** есть навигационная ссылка на страницу «О приложении» из главного приложения

**Критерии приемки:**

- Страница «О приложении» отображает информацию об авторе и ссылку на курс RS School React. [8 баллов]
- Страница «О приложении» доступна через навигационную ссылку из основного приложения. [7 баллов]

### Функция 4: Страница 404 (**10 баллов**)

**Как** пользователь
**Я хочу** видеть четкую страницу 404 при переходе на несуществующий маршрут
**Чтобы** понимать, что страница не существует, и иметь возможность вернуться в приложение

**Сценарий:** Отображение 404 для неизвестных маршрутов

- **При условии**, что я перехожу по несуществующему маршруту
- **Когда** маршрут не соответствует ни одной определенной странице
- **Тогда** я вижу страницу 404 с сообщением о том, что страница не найдена
- **И** есть способ вернуться в основное приложение

**Критерии приемки:**

- Страница 404 отображается для всех неизвестных или несуществующих маршрутов. [3 балла]
- Страница 404 содержит четкое сообщение о том, что страница не найдена. [3 балла]
- Страница 404 предоставляет возможность навигации (например, кнопку или ссылку) для возврата в главное приложение. [4 балла]

## Технические требования

1. **Управление ветками**: Создайте ветку от **"unit-testing"**. Название ветки: **"hooks-and-routing"**

2. **Преобразование компонентов**:
   - Преобразуйте ВСЕ компоненты-классы в **функциональные компоненты** с хуками
   - **Исключение**: оставьте **Error Boundary** как компонент-класс
   - Создайте пользовательский хук для операций с localStorage

3. **Настройка маршрутизации**:

- Добавьте маршрутизацию в режиме SPA, используя либо **React Router** (выберите подход "Data" или "Declarative", см. [API & mode availability](https://reactrouter.com/start/modes#api--mode-availability-table)) **или [TanStack Router](https://tanstack.com/router/latest/docs/installation/manual)**.
- Выберите один маршрутизатор и следуйте его официальной документации для настройки и навигации.

## 📚 Часто задаваемые вопросы (FAQ)

### ❓ Должен ли параметр `page` всегда присутствовать в URL?

Да. Даже если поисковый запрос или детали не выбраны, текущая страница всегда должна отражаться в URL, например `?page=1`.

### ❓ Означает ли требование «Пагинация присутствует и в URL, и на странице» синхронизацию?

Да. Номер страницы в URL должен совпадать с видимым состоянием пагинации. Если пользователь переходит на страницу 3, URL должен измениться на `?page=3`.

### ❓ Следует ли использовать `<Outlet>` для секции деталей?

Да. Как описано в требовании «Мастер-детали», секция деталей должна быть реализована с использованием `<Outlet>` из React Router.

### ❓ Что, если страница «О приложении» существует, но нигде нет ссылки на неё?

Считается, что она реализована частично. Для получения полного количества баллов страница «О приложении» должна существовать **и** быть доступна через навигационную ссылку из главного приложения.

### ❓ Моя страница 404 работает на развернутом сайте, но не работает локально. Это допустимо?

Нет. Страница 404 должна работать **локально**, так как перекрестная проверка выполняется с использованием `localhost`. GitHub Pages или другие хостинги могут переопределять поведение вашей страницы 404.

### ❓ Нужно ли передавать поисковый запрос в URL?

Только если вы хотите. Это не требуется в задании, но вы можете добавить его как параметр запроса `search` (например, `?page=1&search=pikachu`). Однако это не влияет на оценку.

### ❓ Могу ли я использовать `useSearchParams` или `useParams`?

Да. Вы можете выбрать один из них или оба в зависимости от вашей стратегии маршрутизации.

### ❓ Что я должен передавать в параметр `details`?

Вы должны передавать ID (или идентификатор) выбранного элемента из результатов поиска, например `?page=1&details=25`.

### ❓ Мой PR слит в `main`. Это штраф?

Нет. Пока исходный PR существует и ваш код доступен для проверки, автоматического штрафа нет.
Однако слияние в `main` **не рекомендуется**, так как это может усложнить процесс проверки для вашего ментора.
