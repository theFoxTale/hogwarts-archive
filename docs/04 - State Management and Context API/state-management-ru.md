# Управление состоянием и Context API

## Функциональные требования (максимум **100 баллов**)

### Функционал 1: Решение для управления состоянием (**35 баллов**)

**Как** разработчик
**Я хочу** использовать современное решение для управления состоянием (например, Redux Toolkit или Zustand)
**И** использовать Context API исключительно для персонализации темы
**Чтобы** состояние приложения было предсказуемым и масштабируемым, а также чтобы надёжность и поддерживаемость приложения обеспечивались покрытием модульными тестами не менее 80%. Персонализация темы должна быть реализована с использованием Context API (см. Функционал 5), так как это не является частью решения по управлению состоянием.

**Сценарий:** Настройка хранилища состояния

- **Дано** я запускаю приложение
- **Когда** я выбираю решение для управления состоянием (Redux Toolkit или Zustand)
- **Тогда** приложение настроено на использование выбранного решения для управления состоянием

**Критерии приёмки:**

- Redux Toolkit или Zustand интегрированы в приложение. [20 баллов]
- Хранилище состояния настроено должным образом и используется для управления состоянием. [15 баллов]

### Функционал 2: Управление выбранными элементами (**25 баллов**)

**Как** пользователь
**Я хочу** выбирать элементы на дашборде, и чтобы мой выбор сохранялся при навигации
**Чтобы** я мог легко управлять выбранными элементами и просматривать их
**А также** расширить функциональность клика следующим образом, сохраняя существующее поведение:

- Клик по чекбоксу должен только выбирать или снимать выбор с элемента, не открывая панель сведений.
- Клик в любом другом месте элемента (вне чекбокса) должен открывать панель сведений, не влияя на состояние выбора.
- Оба действия должны работать независимо и не мешать друг другу.

**Сценарий:** Сохранение выбора элементов

- **Дано** я просматриваю элементы на дашборде
- **Когда** я выбираю или снимаю выбор элементов с помощью чекбоксов
- **Тогда** мой выбор сохраняется в состоянии приложения
- **И** когда я перехожу между страницами, мой выбор сохраняется

**Критерии приёмки:**

- Каждый элемент имеет чекбокс для выбора. [15 баллов]
- Выбранные элементы хранятся в состоянии и сохраняются при навигации между страницами. [5 баллов]
- Снятие выбора с элемента удаляет его из состояния. [5 баллов]

### Функционал 3: Компонент Flyout для выбранных элементов (**15 баллов**)

**Как** пользователь
**Я хочу** видеть сводку по моим выбранным элементам и иметь быстрые действия
**Чтобы** я мог управлять выбором и легко загружать их

**Сценарий:** Действия во Flyout

- **Дано** у меня выбран хотя бы один элемент
- **Когда** появляется Flyout
- **Тогда** он всегда виден, прикреплён к нижней части страницы с позиционированием sticky
- **И** отображает количество выбранных элементов
- **И** предоставляет кнопки «Снять все» и «Скачать»

**Критерии приёмки:**

- Flyout появляется с липкой позицией (sticky) внизу страницы, когда выбран хотя бы один элемент. [5 баллов]
- Flyout всегда виден и не исчезает при прокрутке. [5 баллов]
- Flyout отображает количество выбранных элементов. [2 балла]
- Кнопки «Снять все» и «Скачать» работают как описано. [3 балла]

### Функционал 4: Скачивание выбранных элементов в CSV (**10 баллов**)

**Как** пользователь
**Я хочу** скачать мои выбранные элементы в CSV-файл
**Чтобы** я мог сохранить и использовать данные вне приложения

**Сценарий:** Скачивание CSV

- **Дано** у меня есть выбранные элементы
- **Когда** я нажимаю кнопку «Скачать» во Flyout
- **Тогда** генерируется CSV-файл, содержащий детали выбранных элементов
- **И** имя файла отражает количество выбранных элементов (например, «15_items.csv»)

**Критерии приёмки:**

- Функция скачивания использует нативные браузерные API (Blob, URL.createObjectURL, a.download). [5 баллов]
- CSV-файл содержит название, описание, URL деталей и другую полезную информацию. [3 балла]
- Имя файла включает количество выбранных элементов. [2 балла]

### Функционал 5: Выбор темы с помощью Context API (**15 баллов**)

**Как** пользователь
**Я хочу** переключаться между светлой и тёмной темами
**Чтобы** я мог персонализировать внешний вид приложения

**Сценарий:** Переключение темы

- **Дано** я использую приложение
- **Когда** я выбираю тему с помощью кнопки, переключателя или выпадающего списка
- **Тогда** внешний вид приложения обновляется в соответствии с выбранной темой

**Критерии приёмки:**

- Выбор темы реализован с использованием Context API. [8 баллов]
- Тема влияет на внешний вид всего приложения. [5 баллов]
- Элемент управления выбором темы доступен в верхней части приложения. [2 балла]

## Технические требования

1. Создайте отдельную ветку для этой задачи от предыдущей ветки. Название ветки: «app-state-management»

2. Настройка управления состоянием:
   - Если используете Redux:
     - Интегрируйте Redux в ваше приложение с помощью Redux Toolkit
     - Настройте Redux store и редюсеры с помощью Redux Toolkit
     - Храните выбранные элементы и их состояние в Redux store
   - Если используете Zustand:
     - Настройте Zustand store
     - Создайте соответствующие срезы (slices) хранилища для управления состоянием выбранных элементов
     - При необходимости реализуйте селекторы

3. Context API:
   - Добавьте контекст для управления темой приложения (светлая или тёмная)

4. Обновление тестов:
   - Обновите ваши тесты в соответствии с изменениями, внедрёнными выбранным решением для управления состоянием и Context API
   - Протестируйте функциональность, связанную с управлением состоянием и переключением темы

## FAQ (Часто задаваемые вопросы)

### ❓ Могу ли я манипулировать DOM напрямую?

Прямые манипуляции с DOM разрешены только для переключения атрибутов темы на `document.documentElement` внутри `useEffect`. Все остальные манипуляции с DOM внутри React-компонентов **запрещены** и будут штрафоваться.

### ❓ Нужно ли использовать localStorage для запоминания выбранной темы?

Использование **Context API обязательно** для реализации переключения темы.
Если вы хотите **сохранять выбор пользователя между сессиями**, вы можете дополнительно использовать `localStorage`, но по умолчанию это не требуется.

### ❓ Нужно ли сохранять выбранные элементы в localStorage?

Нет. Выбранные элементы должны сохраняться только в памяти (состояние приложения) при навигации между страницами в рамках сессии. Нет требования хранить их в localStorage или сохранять при перезагрузке.

### ❓ Можно ли использовать библиотеку для скачивания CSV-файла?

Нет. **Использование любых сторонних библиотек для скачивания файлов строго запрещено.**
Вы должны реализовать функциональность скачивания, используя **нативные браузерные API** (например, `Blob`, `URL.createObjectURL`, `a.download`) без использования сторонних пакетов.

- Выбранные элементы управляются через хранилище состояния, выбранные элементы сохраняются при переходе между страницами – **25**
- Компонент Flyout показывается/скрывается в зависимости от наличия выбранных элементов, отображает количество выбранных элементов – **15**
- Кнопка «Снять все» и кнопка «Скачать» работают согласно требованиям – **10**
- Пользователь может переключать тему приложения с помощью Context API – **15**
