# API запросы в React — чек-лист выполнения

## Функциональные требования (100/100)

| Требование                                                                                                                                                                                   | Баллы | Статус |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- | ------ |
| **API Integration** – интегрирована современная библиотека запросов (RTK Query или TanStack Query), все API-вызовы используют её, реализована инвалидация кэша, TTL настраивается через env. | 25    | ☐      |
| **Data Caching and Loading States** – отображаются индикаторы загрузки, данные кэшируются и переиспользуются при навигации.                                                                  | 25    | ☐      |
| **Error Handling** – ошибки API обрабатываются и показываются пользователю в понятном виде.                                                                                                  | 20    | ☐      |
| **Manual Cache Invalidation** – реализована кнопка ручного обновления, которая инвалидирует кэш и выполняет повторный запрос.                                                                | 10    | ☐      |
| **Test Coverage for Querying** – тесты покрывают состояния загрузки, ошибок и поведение кэширования.                                                                                         | 20    | ☐      |

---

### Feature 1: API Integration (**25 points**)

- [ ] **(+10)** Библиотека запросов (RTK Query для Redux или TanStack Query для Zustand) интегрирована и настроена.
- [ ] **(+5)** Все существующие API-вызовы (`searchCharacters`, `getCharacterById`) переписаны с использованием выбранной библиотеки.
- [ ] **(+5)** Реализована стратегия инвалидации кэша (например, при ручном обновлении или после мутаций, если они есть).
- [ ] **(+5)** Время жизни кэша (TTL / `staleTime`) вынесено в переменную окружения (например, `VITE_CACHE_TTL` или `REACT_APP_CACHE_TTL`).

### Feature 2: Data Caching and Loading States (**25 points**)

- [ ] **(+13)** Во время выполнения запросов (список, детали, поиск) отображаются индикаторы загрузки (спиннеры, скелетоны или текст).
- [ ] **(+12)** Данные, полученные от API, кэшируются. При повторном посещении той же страницы / деталей запрос не выполняется — данные берутся из кэша (проверяется через DevTools сети).

### Feature 3: Error Handling (**20 points**)

- [ ] **(+20)** При ошибке API (сетевой сбой, 404, 500 и т.д.) пользователю показывается понятное сообщение об ошибке вместо "сломанного" интерфейса.

### Feature 4: Manual Cache Invalidation (**10 points**)

- [ ] **(+10)** Добавлена кнопка (или иной элемент управления) для ручного обновления данных. При нажатии:
  - Кэш для соответствующих запросов (список, детали, поиск) инвалидируется.
  - Выполняется повторная выборка данных с сервера.

> _Допустимо сделать одну кнопку для всего приложения или отдельные кнопки для списка и деталей._

### Feature 5: Test Coverage for Querying (**20 points**)

- [ ] **(+20)** Написаны тесты (Jest + React Testing Library), которые проверяют:
  - Отображение состояния загрузки при выполнении запроса.
  - Отображение сообщения об ошибке при неудачном запросе.
  - Поведение кэширования (данные не запрашиваются повторно при повторном монтировании компонента).
  - Работу кнопки ручного обновления (инвалидация + refetch).

## Технические требования и штрафы

### Обязательные условия (без штрафа)

- [ ] Ветка для задания называется `api-queries` и создана от предыдущей ветки `app-state-management`.
- [ ] Все исходные файлы имеют расширения `.ts` или `.tsx` (нет `.js` / `.jsx`).
- [ ] TypeScript используется во всём проекте.
- [ ] Отсутствует использование `any`.
- [ ] Отсутствует использование `ts-ignore`.
- [ ] Отсутствуют code-smells (God-object, дублирование кода, закомментированные участки).
- [ ] Нет нарушений ESLint (ошибки, не предупреждения).
- [ ] Покрытие тестами (statement coverage) не ниже 80%.
- [ ] Нет прямых манипуляций с DOM (исключения: переключение темы на `document.documentElement` и создание ссылки для CSV).
- [ ] Нет мутаций состояния (для Redux/Zustand).
- [ ] Не используются сторонние библиотеки компонентов (Material UI, Ant Design и т.п.).
- [ ] Pull Request соответствует гайдлайну (включая чекбоксы в оценке).
- [ ] Коммиты сделаны до дедлайна.

### Штрафные санкции (если применимо)

- [ ] **Штраф -10 за каждый** API-вызов, не мигрированный на выбранную библиотеку запросов (по данным кода).
- [ ] **Штраф -95** если TypeScript не используется.
- [ ] **Штраф -20 за каждое** использование `any` или `ts-ignore`.
- [ ] **Штраф -10 за каждый** code-smell или закомментированный код.
- [ ] **Штраф -5 за каждое** нарушение ESLint.
- [ ] **Штраф -10 / -30 / -50** за недостаточное покрытие тестами (см. критерии выше).
- [ ] **Штраф -50** за прямое DOM-манипулирование в компонентах (не разрешённое).
- [ ] **Штраф -20 за каждую** мутацию состояния.
- [ ] **Штраф -100** за использование UI-библиотек (Material UI, Ant Design).
- [ ] **Штраф -40** за коммиты после дедлайна.
- [ ] **Штраф -10** за неправильно оформленный Pull Request.
