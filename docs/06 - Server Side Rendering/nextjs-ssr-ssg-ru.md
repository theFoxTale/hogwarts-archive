# Next.js. Серверный рендеринг (SSR)

**Примечание:** Для выполнения этого задания вы также можете использовать экспериментальный фреймворк `vinext`. Он всё ещё экспериментальный, но допускается как опция. Подробнее: https://github.com/cloudflare/vinext.

## Технические требования

1. Создайте отдельную ветку для этого задания от ветки `api-queries` (ветка с вашим поисковым/API-приложением). Название ветки: `nextjs-ssr`.
2. Интеграция Next.js App Router:
    - [Мигрируйте ваше приложение с Vite на Next.js с использованием App Router](https://nextjs.org/docs/app/guides/migrating/from-vite).
    - React-router должен быть удалён. Необходимо использовать файловую маршрутизацию, предоставляемую Next.js (App Router).
    - Возможно, потребуется адаптировать некоторые существующие библиотеки для работы с Next.js (например, Redux).

## FAQ (Часто задаваемые вопросы)

### ❓ Нужно ли переписывать проект с нуля или мигрировать?

Вы должны продолжить работу над вашим поисковым/API-приложением и **мигрировать** его на Next.js App Router.
Ответвитесь от `api-queries`, назовите новую ветку `nextjs-ssr`, замените `react-router` на файловую маршрутизацию и адаптируйте существующий функционал, чтобы он работал в новой среде — сохраняя всё из предыдущих модулей, что не противоречит новым требованиям (отдельный модуль форм исключён).

### ❓ Где развертывать? Разрешён ли GitHub Pages?

Вы можете развернуть проект где угодно — GitHub Pages, Netlify, Vercel или любая другая платформа.
Основная цель — изучить различные варианты развертывания и понять, как они работают.

Имейте в виду, что **Vercel** разработана той же командой, которая создаёт Next.js, и имеет глубокую интеграцию с ним, поэтому стоит ознакомиться с её возможностями и процессом развертывания поближе.

### ❓ Нужно ли переводить данные API?

**Нет.** Локализуйте **интерфейс и навигацию** (тексты интерфейса, заголовки, метки).
Данные API оставляйте как есть, если API не поддерживает несколько языков.

### ❓ Как реализовать интернационализацию в Next.js?

Используйте библиотеку [next-intl](https://next-intl.dev/) для добавления интернационализации. Ваше приложение должно поддерживать как минимум два языка, и пользователи должны иметь возможность переключать языки через клиентский переключатель. Переводить данные API не нужно — только элементы UI и навигации.

### ❓ Как использовать функцию createNavigation для ссылок?

Функция [createNavigation](https://next-intl.dev/docs/getting-started/app-router/with-i18n-routing#i18n-navigation) из next-intl является обёрткой над навигацией Next.js, поддерживающей локали. Используйте её для рендеринга всех навигационных ссылок, чтобы они корректно работали с интернационализацией.

### ❓ Где следует выполнять статические и динамические запросы данных в Next.js?

Все статические (неизменяемые) запросы должны выполняться на сервере с использованием серверных компонентов Next.js или серверного fetch. Динамические запросы (зависящие от параметров поиска или действий пользователя) по-прежнему могут выполняться на клиенте с использованием RTK Query, TanStack Query или подобных библиотек.

### ❓ Когда следует использовать серверные компоненты в Next.js?

Переносите как можно больше рендеринга на сервер. Компоненты, которым не требуется состояние или хуки React, должны быть реализованы как серверные компоненты для лучшей производительности и SEO. См. [документацию Next.js о серверных и клиентских компонентах](https://nextjs.org/docs/app/getting-started/server-and-client-components) для руководства.

### ❓ Как генерировать и отдавать CSV-файлы на сервере?

CSV-файлы (например, создаваемые для загрузки в задании по Redux) должны собираться и отдаваться с сервера с использованием server action или route handler. См. [руководство Next.js по серверным действиям и формам](https://nextjs.org/docs/app/guides/forms) для деталей реализации.

### ❓ Что насчёт изображений и `next/image`?

- Все изображения должны рендериться с помощью `next/image` (если в вашем API нет изображений, вы автоматически получаете баллы по спецификации).
- Для внешних URL настройте `images.domains` или `images.remotePatterns` в `next.config.mjs`.
- Избегайте использования пользовательских загрузчиков, если это не строго необходимо.

### ❓ Где должны выполняться запросы?

- **Статические/неизменяемые запросы** (не зависящие от действий пользователя) → **сервер** (RSC/серверные компоненты, `fetch` в серверном коде).
- **Динамические запросы** (зависящие от `searchParams` или взаимодействия пользователя) → клиент (разрешены RTK Query / TanStack Query).
- Переносите как можно больше компонентов без состояния в **серверные компоненты**.

### ❓ CSV теперь должен генерироваться на сервере. Как?

Используйте **Server Action** или серверный route handler для создания CSV и отправки его с правильными заголовками.

### ❓ Можно ли использовать библиотеку для переключения темы (например, `next-themes`)?

Пожалуйста, **не используйте** внешние библиотеки для переключения темы.
Реализуйте собственное решение вручную:

- Храните состояние темы в **React Context**.
- При желании сохраняйте выбор в **localStorage**.
